# Agent 就绪仓库

仓库是 Agent 的工作环境。Agent 每次进来都没有记忆：它能读到什么、能运行什么、出错时被什么拦住，决定了产出的质量。仓库和 Agent 互相成就：仓库提供术语、指针、一条命令就能跑的验证和护栏；Agent 的每次失误再回流成检查、规则和文档，让下一次运行更稳。

## 三条原则

- **常驻精简，指针精确。** 指令文件每一轮都占上下文，只放 Agent 不看代码就会做错的事；其余内容放进按需读取的文档，用写明触发条件的指针引用。
- **能检查的就不靠叮嘱。** 拦截错误的手段按成本从低到高排：类型、lint、测试、变更检查命令、评审规则、指令文件、文档。每条经验落在最便宜、又确实能拦住它的那一层。
- **环境本身就是事实来源。** 脚本、配置、目录结构能回答的问题不写进文档。文档只记录查不到的东西：约定、理由、陷阱。

## 与其他 Skills 分工

已安装时按下表衔接；未安装时，本 Skill 的参考可以独立执行。

| Skill | 负责 | 本 Skill 的衔接 |
|---|---|---|
| writing-for-agents | 面向 Agent 的写作手法：指针、上下文负载、引导词、无效指令 | 编写指令文件和 Skill 时一并使用；本 Skill 补充仓库结构与文风 |
| setup-matt-pocock-skills | `## Agent skills` 块，以及 `docs/agents/` 下 tracker、triage、domain 的绑定 | 审计时只检查是否存在、内容是否过期；缺失时请用户运行它，不手写替代品 |
| domain-modeling | GLOSSARY.md 与 ADR | 协作角色词汇写进指令文件，领域词汇归它管理 |
| retro | 复盘一次会话，列出可改进的环境问题 | 改进项落在哪一层，按 [经验回流](references/feedback-loop.md) 判断 |
| code-review | 按仓库标准和规格审阅 diff | 确保作者和评审读的是同一份标准 |
| codeup | 云效工作项、合并请求、流水线 | 托管在云效的仓库，追踪与交付交给它；本 Skill 不写平台命令 |

## 共同规则

- 先读仓库现有的指令、文档、脚本、钩子和 CI，再提建议。已有的机制修好或接上，不另起一套。
- 只写仓库中真实存在且已验证的内容。写进文档的命令先在本机跑通；跑不通的标注为未验证。
- 项目专属事实（组织、路径、账号、凭据、真实数据）留在各项目仓库内，不写进本 Skill，也不出现在公开示例里。
- 修改指令文件、钩子、CI 会改变之后所有 Agent 的行为。用户已授权的范围内直接完成；其余先拿出具体 diff 供审阅。
- 规则与当前任务冲突时，明确指出冲突并请人确认，不要悄悄绕过。

## 完成条件

- 审计：每一层标为“已有”“部分”“缺失”或“不适用”，并附证据（文件路径或命令输出）；按影响排序列出最小改动。
- 修改：新增的每行常驻指令都通过 [准入测试](references/instructions.md#准入测试)；新增链接可以打开；写进文档的命令已实际运行。
- 汇报实际改了哪些地方、验证了哪些，以及哪些没有验证。
